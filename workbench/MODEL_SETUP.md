# Yue 2.0 · Token Monster：新实例自动准备模型

启动命令保持不变：`bash /root/YuE/workbench/control.sh start`。

启动后，工作台依次完成：

1. 检查本地固定版本模型，通过校验的文件直接复用。
2. 本地缺失时，优先读取平台已经挂载的 BF16 公共模型。
3. 首次未检测到共享模型时，先等待最多 30 秒让平台挂载就绪；超时仍不可读，或共享文件格式、校验不匹配时，自动从 HF-Mirror 下载固定版本的 YuE2-3B 和 YuE2-Vae。不需要用户创建软链接或填写创作 API Key。
4. 下载完成并通过完整性校验后，页面显示模型就绪。提交音乐任务后才加载 GPU。

镜像只保存程序和配置，不包含旧实例的外部模型盘。`ln -s` 只能建立链接，不能下载文件或挂载平台磁盘。当前共享文件路径为 `/.autodl/ac/d6/61/acd661ae90fcf20f8955a84088c01cce`；新实例不存在该文件时会自动走网络下载。

模型缓存位于 `/root/autodl-tmp/huggingface/hub`，完整文件约 7.79 GB，另需至少 1 GiB 空余。网络速度取决于实例及下载服务，无法保证固定完成时间。

页面可查看实际已下载字节并暂停。关闭页面不会停止后台准备；服务重启后会检查缓存并继续下载。暂停后也可点击“继续准备模型”。下载失败时保留可续传的部分，页面展示实际原因；可以在“网络下载与手动切换来源”中改用 Hugging Face 官方。

共享文件接入与网络下载均使用固定官方文件摘要校验；不会把 INT8 文件冒充 BF16 模型，也不会修改平台共享源文件。

## 发布镜像

更新运行中的实例不会更新已保存的镜像。需要重新保存并发布包含这次代码的镜像，新建实例才会使用新的启动逻辑。保存轻量镜像前先停止服务，再清理模型缓存、用户密钥和私人作品；不要删除代码目录中的 `model-assets`，其中是配置、分词器、许可与文件头，不是模型权重。发布前应从新镜像启动独立实例验证。

## 共享接入诊断

`GET /api/models` 的 `shared_diagnostic` 记录检查路径、错误代码和发生时间；`source_note` 会在页面显示具体切换原因。`shared_missing` 表示检查期限内路径未出现，`shared_unreadable` 表示访问出错，`shared_checksum` / `shared_format` 表示文件校验或格式不符，`assets_missing` 表示代码中配套模型文件缺失。已有完整缓存直接复用时，`source` 为 `cache`，不会发起模型下载。

挂载在网络下载开始后才就绪时，可以暂停下载，再点击“继续准备模型”重新选择来源。30 秒等待是对启动时序的保护，并不能替平台创建缺失的挂载。
